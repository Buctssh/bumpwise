## 结论速览

- **三次运行的人工结论全部复现**: 三次都因为 `test_dotted_aliases_round_trip_without_data_loss` 判为 FAIL; 002 的 4 个枚举缺陷被接口表面对比判为 error, 003 和 004 没有;
- **002 的缺陷第一次被自动发现**: 当时人工检查时, 原有测试, 隐藏测试, 42 个示例的新旧对比都没有发现它, 是手工打印枚举成员才看到的. 现在它是一条 `[error] IoCSeverity: 枚举多出了成员 ['model_config']`;
- **三种运行记录, 三条评分的路径都走通了**: 004 (V3, 照着题目运行) 直接用 `grade` 命令; 003 (V2, 有 trace, 没有题目) 用 `grade --task --repo --python`; 002 (V1, 没有 trace) 只能直接调用 `grade()`, 隔离检查为 skip;
- **评分本身很快, 慢的是准备旧版本**: 每次评分约 30 秒, 其中准备"旧代码 + 旧版本"的环境约 25 秒, 8 项检查约 4 秒;
- **"工作区必须和运行结束时一样"这道检查在真实数据上生效了**: 003 的工作区恢复原样之后再评分, 被拒绝了.

## 怎样评的

**004**: 照着题目运行, 工作区和 trace 都在. 但运行时题目还没有 `[evaluation]`, 所以用 `--task` 指定现在的题目文件:

```
python -m bumpwise grade runs/20261019-155045-cortex-xdr-client-pydantic2-ee4c --task tasks/cortex-xdr-client-pydantic2.toml
```

**003**: V2 的运行, 有 trace, 但 meta 里还没有 `mode` 和工作区的位置. agent 的改动保存在 `workspace/cortex-v1` 的 `run-003` 分支上 (已经提交了),
所以先把它还原成"运行刚结束时"的样子 (未提交的修改), 再评分, 最后恢复:

```
git -C workspace/cortex-v1 -c core.autocrlf=false diff f139b58 run-003 | git -C workspace/cortex-v1 apply
python -m bumpwise grade runs/20261017-202931-cortex-v1-7a3f --task tasks/cortex-xdr-client-pydantic2.toml \
    --repo workspace/cortex-v1 --python workspace/cortex-v1/.venv/Scripts/python.exe --base-python C:/conda/python.exe
git -C workspace/cortex-v1 checkout -- cortex_xdr_client
```

还原之后, 工作区的改动和 003 trace 里的 `diff.patch` 完全一致, 说明还原是准确的. 恢复以后再评一次, `grade` 命令拒绝了: "工作区在运行结束之后被改动过".

**002**: V1 的运行, 没有 trace. 同样从 `run-002` 分支还原, 然后用 [grade_002.py](../grade_002.py) 直接调用 `grade()`. 没有运行记录, 隔离检查只能是 skip.

## 发现的问题

1. **每评一次分, 就多一个旧版本的工作区**: 这次评分新增了 3 个, 加上开发 V4 时验证留下的 2 个, `workspace/runs/` 下一共有 5 个 `*-reference*` 目录, 每个约 28 MB (主要是 venv).
   旧版本的接口表面只取决于题目 (起点提交, 旧版本, 要比较的包), 和是哪次运行无关. 可以按题目缓存, 同一道题只准备一次, 也省掉每次 25 秒;
2. **旧的运行记录缺少字段**: 003 的 meta 没有 `mode` 和工作区的位置, 004 运行时题目还没有评测信息. `grade` 命令的 `--task`, `--repo` 就是为这种情况准备的. 运行记录的格式以后还会变, 读取旧记录时都要考虑"字段不存在";
3. **三次都是 FAIL, 但"差多少"看不出来**: 002 有 2 项失败, 003, 004 只有 1 项, 总评都是 FAIL. 只有 pass / fail 的总评适合"能不能合并"的判断, 比较不同的 agent 或 prompt 时 (V6), 还需要更细的分数, 比如隐藏测试的通过率, 接口表面的 error 数.
