你负责从一次依赖迁移的结果里提炼可以复用的经验. 迁移由另一个 agent 完成, 之后由评分程序检查. 你会看到评分没有通过的检查 (包括 agent 当时看不到的隐藏测试和它们的报错), agent 的最终报告, 以及它调用过的工具的摘要.

# 提炼什么

只提炼能帮助以后的迁移做对的经验: **新旧版本之间的行为差异, 而这次的 agent 没有发现, 或者处理错了**. 每一条都必须有这次的失败作为证据.

- 只有一次偶然的失误 (比如笔误), 或者和这个依赖无关的问题 (比如环境, 网络), 不要提炼;
- 没有值得提炼的经验时, 输出空的数组 [];
- 最多 3 条;
- 已经有的经验不要重复提炼 (见最后).

# 写法的要求 (违反了会被自动退回)

1. **写库本身的行为, 不写这个仓库的细节**: 不能出现这个仓库的文件路径, 类名, 函数名, 字段名, 以及测试的名字. 这条经验要能用在别的仓库上;
2. `trigger_pattern`: 一个 Python 的正则表达式, 用来在**别的仓库**的源代码里, 逐行找出"可能受影响"的写法. 写代码里能看到的现象 (比如某种写法), 不写结果 (比如"测试会失败"). 不要用嵌套的量词 (比如 `(a+)+`) 和反向引用. 实在找不到合适的写法时写 null;
3. `applies_when`: 一句话说明什么样的代码会受影响;
4. `symptom`: 迁移之后会发生什么;
5. `why_tests_miss`: 为什么原有的测试发现不了;
6. `fix`: 怎样改. 如果要用到新版本才有的写法, 写明从哪个版本开始有;
7. `verify`: 怎样用一个最小的实验确认 (比如写一个几行的脚本, 构造对象, 检查结果). 不依赖这个仓库的代码;
8. `id`: 小写字母, 数字和 -, 以依赖和版本开头, 例如 `pydantic2-alias-field-name`;
9. `title`: 一句话, 不超过 40 个字.

# 输出

只输出一个 JSON 数组, 不要输出其他文字:

```json
[{"id": "...", "title": "...", "applies_when": "...", "trigger_pattern": "...", "symptom": "...", "why_tests_miss": "...", "fix": "...", "verify": "..."}]
```
